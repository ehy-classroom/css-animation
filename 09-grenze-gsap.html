09 · Grenze: CSS und GSAP

Was passiert

Beide Bälle fallen, springen immer niedriger nach, stauchen sich bei jedem Aufprall, rollen dabei zur Seite aus und bleiben liegen. Der Schatten folgt. Links reines CSS, rechts die JavaScript-Bibliothek GSAP.

Neu gegenüber 08

Hier wird CSS mühsam: Links musste jeder Aufprall, jede Stauchung und jeder Scheitelpunkt als eigener Keyframe berechnet werden – für den Ball und noch einmal für den Schatten. Rechts erzeugt GSAP ein Sprung-Easing samt passender Stauchung (CustomBounce), eine Timeline legt alle Bewegungen auf eine gemeinsame Zeitachse. Eine Bibliothek lohnt sich bei langen Abfolgen, vielen Elementen und Steuerung zur Laufzeit – um den Preis einer zusätzlichen Abhängigkeit.

Bedienung

„Wiederholen“ lädt die Seite neu. Braucht eine Internetverbindung, weil GSAP nachgeladen wird.

CSS

@keyframes ausschwingen {
  0%  { transform: translateY(0) scale(1, 1); }
  25% { transform: translateY(144px) scale(1, 1); }
  27% { transform: translateY(144px) scale(1.4, 0.6); }
  29% { transform: translateY(144px) scale(0.8, 1.25); }
  45% { transform: translateY(80px) scale(1, 1); }
  /* … 9 weitere Stufen, dazu Easing je Stufe
     und alles noch einmal für den Schatten */
}

JS

CustomBounce.create('aufprall', {
  strength: 0.6,
  squash: 2,
  squashID: 'aufprall-squash'
});

gsap.timeline({ delay: 1, defaults: { duration: 1.5 } })
  .to(ball, { y: 144, ease: 'aufprall' }, 0)
  .to(ball, { scaleX: 1.4, scaleY: 0.6,
              ease: 'aufprall-squash' }, 0)
  .to(schatten, { scale: 1, ease: 'aufprall' }, 0)
  .to(bahn, { x: 60, ease: 'power2.out' }, 0);
