21 · animation-fill-mode

Worum es geht

Eine Animation wirkt nur, solange sie läuft – nicht während der Verzögerung und nicht danach. Davor und danach gilt das eigene CSS des Elements. Unterscheiden sich eigenes CSS und Keyframes, springt das Element. backwards füllt die Wartezeit mit dem ersten Keyframe, forwards hält den letzten fest, both macht beides.

Drei Fälle

1 · Kacheln erscheinen nacheinander. Ohne backwards sind sie in ihrer Wartezeit schon da, verschwinden beim Start und blenden dann ein.

2 · Gespeichert blendet nach 1,5 s aus. Ohne forwards steht die Meldung danach wieder da.

3 · Neue Version fährt nach 1,5 s herein, steht kurz und fährt wieder hinaus. Ohne both ist der Hinweis in der Wartezeit sichtbar und am Ende wieder da.

Und none?

Die Voreinstellung ist richtig für alles, was endlos läuft oder ohnehin im eigenen CSS endet: Ladeanzeige, wackelnde Glocke.

1 · backwards

@keyframes einblenden {
  from { opacity: 0; }
}
.kachel {
  animation: einblenden 0.5s ease-out backwards;
  animation-delay: calc(0.5s + var(--i) * 0.35s);
}

2 · forwards

@keyframes ausblenden {
  to { opacity: 0; }
}
.gespeichert {
  animation: ausblenden 0.5s ease-in 1.5s forwards;
}

3 · both

/* eigenes CSS: sichtbar am Platz;
   Keyframes beginnen und enden außerhalb */
.hinweis {
  animation: kommen-und-gehen 3s 1.5s both;
}
